## Comment lire un fichier

Chaque page suit la même structure :

1. **Paramètres techniques** — URL, title SEO, meta description, H1, mots-clés, objectif.
2. **Sections numérotées** — dans l'ordre d'affichage, avec le niveau de titre (H1/H2/H3), le texte exact, les libellés de boutons et les liens.
3. **Notes développeur** — visuels attendus, ancres, comportements.

Les mentions `[À FOURNIR : …]` signalent une information que nous n'avons pas encore.
**Ne pas inventer** : soit l'info est fournie, soit la mention est retirée avec la section.

## Règles de rédaction appliquées

- **Ton** : clair, direct, informatif. On présente un projet immobilier sérieux, pas une promotion agressive.
- **Phrases courtes**, vocabulaire simple, pas de jargon technique ni de superlatifs empilés.
- **Titres** : accrocheurs mais factuels. Un titre annonce ce que la section contient.
- **Longueur** : paragraphes de 2 à 3 phrases. Ni pavés, ni fragments.
- **Chiffres** : toujours les mêmes formulations d'une page à l'autre (voir ci-dessous).
- **Pas de promesse non vérifiée** : la livraison est prévisionnelle, l'éligibilité à l'aide au logement se vérifie au cas par cas.

## Règles SEO appliquées

- **Un seul H1 par page**, contenant le mot-clé principal ou son contexte.
- **Title** ≤ 60 caractères · **Meta description** ≤ 155 caractères.
- Hiérarchie **H2 → H3** respectée, jamais de saut de niveau.
- Mots-clés placés naturellement dans les titres et le premier paragraphe.
- Maillage interne : chaque page renvoie vers 2 à 3 autres pages du site.
- Texte alternatif prévu pour chaque visuel (voir notes développeur).
- Données structurées recommandées : `Residence` / `Product` / `FAQPage` (voir `07-faq.md`).
